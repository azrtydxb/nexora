- `scripts/kw-acceptance.sh` passed all five top-level tests in 160.537s after recovery (local evidence `/tmp/nexora-acceptance-recovery.log`).
- Local fix (not yet deployed): serialize hub registration and cleanup with their database writes in `mgmt/internal/control/server.go` and `hub.go`. The lifecycle mutex is separate from the broadcast mutex; connection database operations have a five-second timeout. `TestConnectionPersistenceHoldsLifecycleLock` verifies both persistence callbacks hold the lifecycle lock, broadcasts remain unlocked, and superseded cleanup cannot clear the replacement. Removing the lifecycle locks in the dev copy made this test fail; restoring them passed the control package with `-race`. This fixes the identified ordering gap, but does not prove it caused the live incident. Connection transitions on one instance serialize; a database stall can delay new connections, though broadcasts continue.
- Local AI test fixes: explicit snake_case task error tags; bounded replacement submissions only for busy/timeout (not invalid output); strict token and invalid-output assertions restored; Prometheus errors fail instead of silently returning zero; finite metric values required; capacity forecast must have a newer run than the pre-request baseline; MCP calls bounded to 30 seconds.
